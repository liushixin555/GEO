## 功能说明

建立完整的多层权限体系，确保每个 API 接口和前端页面都受到正确的权限控制。权限规范为铁律级别，详见 `permissions.md`。

### 角色定义

| 角色 | 标识 | 权限范围 |
|------|------|----------|
| 系统管理员 | sysadmin | 全系统无限制访问，包括系统管理和公司管理 |
| 运营者 | admin | 管理被授权的项目 |
| 查看者 | view | 只读访问 GEO 成绩，仅查看被分配的项目 |

### 四层权限架构

每个 API 请求必须依次通过四层校验：

**第1层：反爬虫 + 限流**
- 所有 API 请求必须携带有效的 User-Agent（至少 10 个字符）
- 同一 IP 每分钟超过 200 次请求自动封禁 10 分钟
- 超出限流阈值返回 429 错误

**第2层：JWT 认证**
- 所有 API（除 `POST /api/auth/login`）必须在请求头中携带有效的访问令牌
- 无令牌或令牌过期返回 401 错误

**第3层：角色校验**
- 每个接口明确允许哪些角色访问
- 角色不在允许列表中时返回 403 错误

**第4层：业务逻辑隔离**
- 在接口处理逻辑中进一步校验数据归属关系
- 防止用户访问或操作不属于自己的数据

### 各模块权限矩阵

**技能管理**

| 操作 | 系统管理员 | 运营者 |
|------|-----------|-----------|
| 读取 | 所有技能 | 所有技能 |
| 创建 | 所有技能 | 可创建（自动标记创建者） |
| 修改 | 所有技能 | 仅自己创建的 |
| 删除 | 所有技能 | 仅自己创建的 |

**项目管理**

| 操作 | 系统管理员 | 运营者 |
|------|-----------|-----------|
| 读取 | 所有项目 | 本公司项目 |
| 创建 | 所有项目 | 仅本公司 |
| 修改 | 所有项目 | 本公司项目，不可转移到其他公司 |
| 删除 | 所有项目 | 本公司项目 |

**用户管理**

| 操作 | 系统管理员 | 运营者 | 查看者 |
|------|-----------|-----------|--------|
| 全部操作 | ✅ | ❌ | ❌ |

## 业务规则

1. **所有 API（除登录）必须通过四层校验**
2. **`/api/companies` 仅限公司管理页面使用** — 其他页面需要公司数据必须走 `/api/auth/companies`
3. **系统管理员账号不可被修改角色或删除**
4. 每次新增 API 或页面时，必须完成权限检查清单（见 permissions.md 第七章）
