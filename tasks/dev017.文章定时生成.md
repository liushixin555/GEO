# dev017. 文章定时生成

> 状态：✅ 已完成

---

## 功能说明

使用 node-cron 实现后台定时任务，自动处理状态为 `generating` 的文章，调用 LLM 生成文章内容。

### 定时任务机制

- 基于 node-cron 调度，cron 表达式可通过系统配置管理
- 任务开关可通过系统配置控制（article_generation_enabled）
- 一次获取**所有** `generating` 状态的文章（按 updatedAt 升序，不限制数量）
- 文章逐篇处理：调用 LLM → 写入数据库 → 更新状态 → 下一篇
- 执行中标记 `isRunning` 防止并发重复执行

### 文章生成流程

1. 从数据库查询**所有** `status = 'generating'` 的文章（按更新时间升序，无数量限制）
2. 获取文章**最近一个版本的内容**（previousContent），拼接到 LLM 提示词供参考
3. 获取文章所属项目的知识库图片资源
4. 获取文章关联的技能名称
5. 调用 LLM 服务生成文章内容（传入标题、关键词、画像、图片、技能、历史版本内容）
6. **已有标题不可修改**，始终保留原标题（标题拼接到提示词要求 LLM 使用指定标题）
7. 无标题时从生成内容的首行提取
8. 创建新版本记录（ArticleVersion）
9. 更新文章内容、版本号，状态改为 `pending_review`
10. 生成失败则标记为 `generate_failed`

### 配置项

| 配置键 | 说明 | 默认值 |
|--------|------|--------|
| `article_generation_enabled` | 是否启用定时任务 | 从 config 读取 |
| `article_generation_interval` | cron 表达式 | 从 config 读取 |

---

## API 接口

无独立 API，通过系统配置（`/api/system-configs`）管理开关和 cron 表达式。

---

## 业务规则

1. 同一时间只允许一个批次在执行，防止并发冲突
2. 每篇文章生成失败不影响其他文章处理
3. **已有标题不可修改**，始终保留原标题并拼接到 LLM 提示词
4. 标题为空时自动从内容首行提取（去除 Markdown 标题标记 `#`）
5. 版本号为整数递增
6. 生成内容同时写入 ArticleVersion 版本表和 Article 内容字段
7. 获取最近一个版本的内容作为参考，拼接到 LLM 提示词，指导 LLM 基于历史内容优化改写
