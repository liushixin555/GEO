## 功能说明

待办任务管理系统，支持手工创建和系统自动生成待办事项，提供按优先级、状态、责任人的多维度筛选和操作能力。

### 待办列表页

- **搜索框**：按任务名称搜索
- **四个 Tab 切换**：我的待办、我的已办、全部待办、全部已办
  - 我的待办/已办：当前登录用户为责任人的待办
  - 全部待办/已办：当前用户权限范围内可见的所有待办（sysadmin 看全部，admin/view 看本公司的）
- **过滤条件**：优先级 P0~P4 筛选（P0 最高，P4 最低）
- **手工输入按钮**：打开新建待办弹窗/页面
- **表格列表**（>=1280px 显示表格视图，<1280px 显示卡片视图）
  - 表格列：任务名称、优先级、来源、公司、项目、对象、责任人、状态、创建时间、操作
  - 卡片视图：信息与表格一致，响应式排列
- **分页**：支持分页浏览
- **操作列**：
  - 查看日志：弹出操作日志列表
  - 转交：处理中(处理中)状态的待办可转交给其他人处理
  - 驳回：将待办状态改为草稿，草稿状态的责任人规则——新建者负责；系统自动创建的由 sysadmin 负责
  - 完成：将待办状态改为完成

### 新建/编辑待办

- **手工输入**：填写任务名称、优先级（P0~P4）、对象类别、对象id、操作描述
- **来源标记**：手工录入
- **自动生成**（系统自动创建，来源标记为：内容迭代/智能关联/每日检测/风险预警）

### 待办状态
- 草稿：被驳回或者重新打开的待办转为草稿状态
- 处理中：待办提交后即为处理中，处理中状态
- 关闭：点击完成后，待办状态为关闭状态

## 数据模型

### Todo（待办）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | Int (自增) | 主键 |
| title | String | 任务名称 |
| companyId | Int (外键) | 所属公司 |
| projectId | Int? (外键) | 所属项目（可选） |
| objectType | String | 对象类别（如：文章、关键词、画像等） |
| objectId | Int? | 对象 id |
| action | String | 对对象执行的操作描述 |
| source | Enum | 来源：manual（手工录入）/ content_iteration（内容迭代）/ smart_link（智能关联）/ daily_check（每日检测）/ risk_warning（风险预警） |
| priority | Enum | 优先级：P0/P1/P2/P3/P4，P0 最高 |
| assigneeId | Int (外键) | 责任人（关联 User） |
| status | Enum | 状态：open（处理中）/ closed（关闭）/ draft（草稿） |
| createdById | Int (外键) | 创建人（关联 User） |
| createdAt | DateTime | 创建时间 |
| updatedAt | DateTime | 更新时间 |
| deletedAt | DateTime? | 软删除时间 |

### TodoLog（待办操作日志）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | Int (自增) | 主键 |
| todoId | Int (外键) | 关联待办 |
| operatorId | Int (外键) | 处理人（关联 User） |
| action | Enum | 操作类型：submit（提交）/ close（关闭）/ reopen（重新打开）/ transfer（转交）/ reject（驳回） |
| objectType | String? | 对象类别 |
| objectId | Int? | 对象 id |
| remark | String? | 备注信息（如转交目标用户名等） |
| createdAt | DateTime | 操作时间 |

## API 接口

### 待办管理

| 接口 | 方法 | 说明 | 权限 |
|------|------|------|------|
| `/api/todos` | GET | 获取待办列表（支持 Tab 切换、优先级筛选、搜索、分页） | 登录用户 |
| `/api/todos/:id` | GET | 获取待办详情 | 登录用户 |
| `/api/todos` | POST | 创建待办（手工输入） | sysadmin/admin |
| `/api/todos/:id` | PUT | 更新待办（只有不是关闭状态的待办才可更新） | sysadmin/责任人 |
| `/api/todos/:id/close` | POST | 关闭待办（待办状态为完成） | sysadmin/责任人 |
| `/api/todos/:id/reopen` | POST | 重新打开待办（待办由完成改为草稿状态） | sysadmin/责任人 |
| `/api/todos/:id/transfer` | POST | 转交待办 | sysadmin/责任人 |
| `/api/todos/:id/reject` | POST | 驳回待办（改为草稿状态） | sysadmin/责任人 |

### 待办操作日志

| 接口 | 方法 | 说明 | 权限 |
|------|------|------|------|
| `/api/todos/:id/logs` | GET | 获取待办操作日志列表 | 登录用户 |

## 业务规则

1. **权限控制**：
   - sysadmin 可查看和操作所有待办
   - admin 可查看和操作自己公司范围内的待办
   - view看不到待办页
   - 我的待办/已办 Tab 仅显示当前用户为责任人的记录
2. **优先级**：P0（紧急）> P1（高）> P2（中）> P3（低）> P4（最低），默认 P2
3. **来源分类**：
   - 手工录入：用户手动创建
   - 内容迭代：基于AI知识库/文章管理的内容变更自动生成
   - 智能关联：基于AI分析智能关联生成
   - 每日检测：系统每日自动检测生成
   - 风险预警：系统检测到风险自动生成
4. **状态流转**：
   - 创建 → open（处理中）
   - open → closed（关闭）
   - closed → open（重新打开）
   - open → draft（驳回，回到草稿状态）
   - draft → open（提交）
5. **转交规则**：只有处理中状态的待办可以转交，转交时需选择目标责任人
6. **驳回规则**：驳回后状态变为草稿，责任人变更规则：
   - 用户创建的待办 → 责任人回退为创建者
   - 系统自动创建的待办 → 责任人回退为 sysadmin
7. **删除**：采用软删除（deletedAt 字段）
