# dev028. EvidenceCard V1.1 抽取候选

## 功能说明

新增 EvidenceCard V1.1 抽取候选工具函数，用于从知识库材料中调用 LLM 抽取候选证据卡片，并在入库前完成 JSON 解析、防御性清洗和候选过滤。

本任务只提供后端工具能力，不新增前端页面，不直接写入 EvidenceCard 数据库。

## 实现范围

- 新增 `apis/utils/evidence-extraction.util.ts`
- 从 `apis/utils/index.ts` 导出：
  - `buildEvidenceExtractionPrompt`
  - `parseEvidenceExtractionOutput`
  - `extractEvidenceCandidates`

## 输入输出

输入：

```ts
{
  sourceType,
  sourceText,
  sourceId?,
  sourceUrl?,
  companyId?,
  projectId?
}
```

输出：

```ts
{
  candidates,
  warnings,
  rawText?
}
```

## 业务规则

- Prompt 要求 LLM 只输出 `{ "cards": [...] }` JSON，最多 8 条。
- 材料不足时返回空数组。
- 不得编造客户、数字、资质、荣誉、案例、合作结果或承诺。
- 不抽取“专业可靠、经验丰富、助力企业发展、提升竞争力、行业领先、优质服务”等空泛营销表达。
- 模型输出不可信，解析层支持 ```json 代码块剥离，非 JSON 返回 warning，不抛未处理异常。
- 字段缺失或非法时丢弃候选。
- `keywords` / `articleTypes` 规范为 `string[]`，`articleTypes` 为空时回退 `["general"]`。
- `confidenceScore` / `freshnessScore` / `score` 强制限制在 0-1。
- 抽取候选 `status` 永远强制为 `draft`，不得允许模型生成 `verified`。
- 候选只返回给调用方，不直接入库。

## 2026-06-30 portrait/image 抽取入口补充

- portrait/image sourceId 抽取入口接入 `POST /api/v1/evidence-cards/extract`，第一版由前端直接 `save=true` 保存 draft。
- portrait 抽取读取画像 `title/content`，保存 `sourceType=portrait`、`sourceId=画像ID`、`sourceQuality=portrait`。
- image 抽取读取图片 `title/description/imageUrl`，保存 `sourceType=image`、`sourceId=图片ID`、`sourceUrl=imageUrl`、`sourceQuality=image`，候选 `evidenceType=image_description`。
- 后端读取 portrait/image 源材料时必须按知识库 scope 校验当前用户权限；前端按钮只对 sysadmin/admin 展示。
- 详情页和知识库画像/图片列表均提供“抽取证据”按钮；成功后跳转 `/knowledge/evidence-cards?status=draft` 供审核。

## 2026-06-30 V1.1.1 后端 LLM 抽取增强

- `POST /api/v1/evidence-cards/extract` 自动抽取路径先调用 `extractEvidenceCandidates()` 进行 LLM 候选抽取，复用系统已启用 LLM 模型配置，不新增外部依赖。
- LLM 未配置、调用失败、输出非 JSON、候选全被过滤或返回空数组时，回退当前 deterministic 分段抽取。
- 前端提交 `save=true + candidates` 时不重新调用 LLM，但后端仍会二次清洗、去重并通过 `toCreateData({ status: 'draft' })` 强制保存草稿。
- 抽取 prompt 要求只输出 `{ "cards": [...] }` JSON，最多 8 条，并要求每条候选带 `extractionReason`，必要时带 `warnings`。
- parser 支持 ```json fence 剥离，JSON.parse 失败返回 warning，非法 `evidenceType` / `sourceQuality` 候选丢弃，`keywords` / `articleTypes` 规范为字符串数组，分数限制在 0-1。
