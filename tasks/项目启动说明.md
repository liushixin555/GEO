# 项目启动说明

适用环境：Windows PowerShell，本地项目目录为 `D:\GEO\git_code\by_geo`。

## 1. 日常启动流程

每次重新开机、关闭过前后端或关闭过 PostgreSQL 后，按下面顺序启动。

### 1.1 进入项目目录

```powershell
cd D:\GEO\git_code\by_geo
```

### 1.2 启动 PostgreSQL 服务

如果 PostgreSQL 是 Windows 服务安装，执行：

```powershell
Start-Service postgresql*
```

检查服务是否运行：

```powershell
Get-Service postgresql*
```

检查 5432 端口是否监听：

```powershell
netstat -ano | findstr :5432
```

如果能看到 `LISTENING`，说明数据库端口已启动。

### 1.3 确认数据库可连接

按当前本地配置，数据库名通常是 `geo_ts`，密码使用你本机 PostgreSQL 的密码。

```powershell
psql -U postgres -h localhost -p 5432 -d geo_ts
```

进入 `psql` 后退出：

```sql
\q
```

如果提示密码错误，优先检查项目 `.env` / `.env.local` 里的 `DATABASE_URL` 是否和你本机 PostgreSQL 用户、密码、数据库名一致。

### 1.4 启动项目

正常开发启动：

```powershell
npm.cmd run dev
```

启动后访问：

- 前端：`http://localhost:3000/`
- 后端：`http://localhost:8080/`

注意：直接访问 `http://localhost:8080/` 返回“接口不存在”是正常的，因为后端根路径不是业务 API。后端健康检查可访问：

```text
http://localhost:8080/api/health
```

## 2. 首次启动或代码更新后需要执行

如果你刚拉取代码、切换分支、或我修改过 Prisma schema，需要先执行数据库迁移和 Prisma Client 生成。

```powershell
cd D:\GEO\git_code\by_geo
npm.cmd run db:migrate
npm.cmd run db:generate
npm.cmd run dev
```

如果 `db:generate` 报 Windows DLL 占用，通常是后端服务正在运行。先在运行 `npm.cmd run dev` 的窗口按：

```powershell
Ctrl + C
```

然后重新执行：

```powershell
npm.cmd run db:generate
npm.cmd run dev
```

## 3. 只启动前端或后端

只启动后端：

```powershell
npm.cmd run dev:api
```

只启动前端：

```powershell
npm.cmd run dev:page
```

一般情况下建议直接用：

```powershell
npm.cmd run dev
```

它会同时启动前端和后端。

## 4. 关闭项目

在运行 `npm.cmd run dev` 的终端窗口按：

```powershell
Ctrl + C
```

如果提示是否终止批处理任务，输入：

```powershell
Y
```

如果只想关闭 PostgreSQL 服务：

```powershell
Stop-Service postgresql*
```

再次启动项目前，需要重新执行 PostgreSQL 启动步骤。

## 5. 防止测试阶段触发真实发布收费

发布计划定时器会处理到期的发布计划。测试阶段不要创建“尽快执行”的真实发布计划。

更稳妥的方式是在 `.env` 或 `.env.local` 中确认以下配置：

```env
CRON_PUBLISHING_ENABLED=false
CRON_PUBLISHING_ORDER_SYNC_ENABLED=false
```

修改 `.env` 后必须重启后端：

```powershell
Ctrl + C
npm.cmd run dev
```

如果你需要测试“创建发布计划”但不想真实发布，建议选择未来时间，例如明天或更晚。

## 6. 常见问题

### 6.1 前端提示“接口不存在”

常见原因是后端没有重启，新增接口还没加载。

处理方式：

```powershell
Ctrl + C
npm.cmd run dev
```

如果仍然存在，确认访问的是前端地址 `http://localhost:3000/`，而不是直接操作后端根路径。

### 6.2 登录密码错误

如果执行过数据库种子：

```powershell
npm.cmd run db:seed
```

默认账号通常会重置为：

```text
用户名：sysadmin
密码：sysadmin123
```

如果没执行 seed，则以当前数据库中的用户数据为准。

### 6.3 pnpm 不能用

当前可以优先使用 npm：

```powershell
npm.cmd run dev
npm.cmd run lint
npm.cmd run build
```

不需要强行使用 `pnpm`。
