# 自动发布第一版：收藏渠道与批量创建发布计划

## 背景

当前审核通过后的文章需要运营人员手工进入发布计划页面逐篇选择发布平台。业务期望是：先收藏一批常用渠道，再批量选择待发布文章，一键自动分配渠道并创建发布计划。

## 本次实现范围

第一版保持文章与发布计划解耦，不改变原有手工发布流程和发布执行器逻辑，只新增自动创建发布计划能力。

## 后端改动

- `publishing_platforms` 新增 `is_favorite` 字段，用于标记自动发布渠道池。
- 新增接口：`PUT /api/v1/publishing-platforms/:id/favorite`
  - 请求体：`{ "is_favorite": true | false }`
  - 用于收藏或取消收藏发布平台。
- 新增接口：`POST /api/v1/publishing-schedule/auto`
  - 请求体包含文章 ID 列表、平台匹配策略、排期策略。
  - 只从已收藏平台中分配渠道。
  - 每篇文章只创建一个发布计划，计划内只包含一个平台。
  - 如果文章不是 `approved`，或已有 `pending/publishing/published` 发布计划，则拒绝创建。

## 前端改动

- 在新建发布计划页面的平台表格中新增“收藏”列，可星标常用渠道。
- 在文章管理页表格中支持批量选择文章。
- 只有“已通过且未排期”的文章可以被选择自动发布。
- 新增“一键自动发布”弹窗：
  - 支持循环匹配渠道。
  - 支持随机匹配渠道。
  - 支持尽快执行、指定时间执行、指定时间之后执行。

## 验收点

1. 在发布计划页面收藏至少一个发布平台。
2. 在文章管理页选择多篇“已通过 / 可发布”文章。
3. 点击“一键自动发布”，选择匹配策略并提交。
4. 系统为每篇文章创建一个发布计划，每个计划只包含一个平台。
5. 已有有效发布计划的文章不能再次被选择自动发布。

## 注意事项

- 本次包含数据库字段变更，需要执行 Prisma migration 后才能在本地运行。
- 如果 `npx prisma generate` 报 Windows DLL 占用，需要先停止正在运行的后端服务，再重新执行生成或迁移命令。
