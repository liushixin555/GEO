# dev024. 审计日志管理

> 状态：✅ 已完成

---

## 功能说明

将系统日志（auth 事件、API 4xx/5xx 访问日志）从控制台 stdout/stderr 持久化到 PostgreSQL 数据库，并新增 sysadmin 专属的日志管理页面，支持查看、筛选和分页浏览。

### 日志写入

- **入口1**：`apis/utils/logger.util.ts` — 每个 log 方法（info/warn/error/debug）在控制台输出后追加 `writeAuditLog()` 数据库写入
- **入口2**：`apis/app.ts` api_access 中间件 — 4xx/5xx 响应在控制台输出后追加 `writeApiAccessLog()` 数据库写入
- **写入策略**：即发即弃（fire-and-forget），`.catch()` 静默处理失败，不阻塞请求处理

### 日志查询 API

- `GET /api/v1/audit-logs` — 分页查询审计日志，支持筛选
  - 参数：page, pageSize, level, event, startDate, endDate, search
  - 仅 sysadmin 可访问
- `GET /api/v1/audit-logs/events` — 获取所有不重复的事件类型列表
  - 仅 sysadmin 可访问

### 日志管理页面

- 路径：`/audit-log`
- 角色：仅 sysadmin
- 功能：
  - 搜索框：搜索事件/URL/IP
  - 级别筛选：DEBUG/INFO/WARN/ERROR
  - 事件筛选：动态加载所有事件类型
  - 日期范围筛选：RangePicker
  - 表格列：时间(formatDateTime) | 级别(Tag) | 事件 | 用户ID | IP | 请求(method+url+status) | 耗时
  - 详情展开行：显示完整 metadata

---

## 业务规则

1. 审计日志不可变 — 无 updatedAt/deletedAt，只增不改不删
2. 写入失败不阻塞请求 — fire-and-forget 模式
3. 仅 sysadmin 可查看日志 — 路由守卫 + API 权限校验双重拦截
4. debug 级别日志仅在 LOG_LEVEL=debug 时写入控制台，但始终写入数据库

## 数据模型

### audit_logs 表

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | SERIAL | PK | 主键 |
| level | AuditLogLevel | NOT NULL DEFAULT 'info' | 日志级别（debug/info/warn/error） |
| event | VARCHAR(100) | NOT NULL | 事件名称（如 auth.login.success） |
| user_id | INTEGER | NULL | 关联用户 ID |
| ip | VARCHAR(45) | NULL | 客户端 IP |
| method | VARCHAR(10) | NULL | HTTP 方法 |
| url | VARCHAR(500) | NULL | 请求 URL |
| status | INTEGER | NULL | HTTP 状态码 |
| duration | INTEGER | NULL | 请求耗时（ms） |
| metadata | JSONB | NULL | 额外元数据（username、error message 等） |
| created_at | TIMESTAMPTZ | NOT NULL DEFAULT now() | 创建时间 |

索引：level、event、created_at
