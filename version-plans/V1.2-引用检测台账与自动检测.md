# V1.2 引用检测台账与自动检测

## 一、版本目标

V1.2 目标是把已发布文章的 AI 引用检测从“可手动触发、可看到粗略结果”推进到“可追溯、可复检、可自动扫描、可交接维护”的闭环。

本阶段不做新的 EvidenceCard 业务能力，不做向量库，不做 ContentMission，不做复杂诊断评分系统。重点是围绕已发布链接形成：

```text
published_article_links
-> 自动/手动检测 run
-> source 级引用记录
-> 文章台账列表
-> 详情抽屉追溯问题、回答、来源、片段
-> articleLink 级 24 小时防重复
```

## 二、已完成范围

### 1. 引用检测台账

- `/citation-diagnosis` 隐藏后台继续作为引用检测台账入口，不进入侧边栏。
- 台账列表面向非技术人员展示发布链接、引用模型和命中次数。
- 详情抽屉调用 `GET /api/v1/citation-diagnosis/ledger/:articleId/details`。
- 详情展示检测问题、AI 回答、引用来源、引用片段和命中片段。
- 详情接口不可用或暂无数据时展示“暂无检测详情”，不阻塞列表、搜索、导出和手动复检。

### 2. 来源解析与命中规则

- run-auto 检测问题改为真实用户咨询口吻，避免“是否被引用”这类检测口吻。
- 自动检测 prompt 不直接提供我方已发布 URL，不强迫或诱导模型引用我方链接。
- 引用命中只按 URL 标准化匹配；标题、来源名、摘要或模型口头提及不能算作命中。
- `extractSources` 兼容嵌套 `sources` / `citations` / `references` / `search_results` / Responses annotations 等结构。
- source 级记录保留 `rawSource`、`citationSnippet`、`answerSnippet`、`sourceIndex`。
- 缺少模型配置或 API Key 返回 `skipped`；单模型 API 报错返回 `error`，不阻断同批次其他模型。

### 3. 发布后自动检测

- 新增 `apis/scheduler/citation-detection.scheduler.ts`。
- 发布同步只负责写入 `published_article_links`，引用检测异步执行，不阻塞发布流程。
- 默认每 30 分钟扫描一次，可通过 `CRON_CITATION_DETECTION_INTERVAL` 覆盖。
- 可通过 `CRON_CITATION_DETECTION_ENABLED=false` 禁用。
- 每轮最多处理 5 条发布链接；每条最多 2 个问题、2 个模型。
- `ai_citation_detection_runs.target_article_link_id` 用于 articleLink 级 24 小时防重复。
- 单条链接检测失败不影响其他链接；平台 `skipped` 不算系统失败。
- 自动检测日志不得打印 API Key 或完整敏感配置。

### 4. Prompt 按 skill 拆分

- 新增 `apis/utils/article-prompt-builder.util.ts`，从 `llm.service.impl.ts` 拆出文章生成 prompt 组装逻辑。
- `llm.service.impl.ts` 继续负责模型调用、EvidenceCard retrieval、debug 写入、重写和修复流程。
- Builder 返回 `systemPrompt`、`userPrompt`、`requiredReferenceFiles`、`promptWarnings`、`skillDirs`、`evidencePromptSection`、`evidenceStats`。
- ranking 规则已拆为独立函数，comparison / guide / faq / brand / case 先保留空函数作为后续 skill 专属规则扩展点。
- EvidenceCard 检索没有迁入 builder；builder 只负责 prompt 组装。

### 5. EvidenceCard 与文章生成稳定性

- 文章生成调度器捕获单篇异常后，写入 `generate_failed` 前回读文章状态、版本、最新 ArticleVersion 和带版本 ArticleGenerationDebug。
- 如果生成事务已经提交，调度器跳过失败状态覆盖，避免 `Connection error` 把已生成文章误标失败。
- ArticleGenerationDebug.warnings 增加基础风险词扫描，当前写入 `RISK_TERMS_FOUND`，只供人工审核，不阻塞生成。
- EvidenceCard 文章生成验收继续同时检查 `evidencePromptPreview`、`evidenceStats`、ArticleEvidenceCard `evidenceSnapshot` 和正文质量。

## 六、仍未完成事项

1. 需要用真实发布链接观察自动检测调度器至少 1-2 轮，确认 `target_article_link_id` 24 小时去重符合预期。
2. 需要人工复核多个模型的 `rawSource` 格式，继续补充 `extractSources` 对新结构的兼容。
3. 需要补充引用检测详情接口的回归覆盖，特别是 skipped/error run、无 citation record、无发布链接的展示。
4. Prompt builder 目前只把 ranking 规则实质拆出；comparison / guide / faq / brand / case 仍需按 skill 逐步补齐。
5. EvidenceCard 自测仍需完成 30 条原始材料 -> 20 条 verified -> 3-5 篇文章重生成的人工质量闭环。
6. 引用检测仍只判断“来源 URL 是否命中”，不判断模型回答是否真正采用了我方观点。
